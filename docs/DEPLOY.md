# Deploy, monitor, roll back

## Targets

| Target | How | Status |
|---|---|---|
| Hugging Face Space (Docker SDK, port 7860) | GitHub Actions `deploy` job uploads the repo; the Space builds the root `Dockerfile` (API + UI + RQ worker + Redis + Chroma server under supervisord) | Image **built and smoke-tested locally** (3.46GB, CPU torch); deploy workflow **needs your Space + secrets** (below) |
| Local multi-service | `docker compose up --build` (api, worker, redis, chroma) | **Run locally**: all 4 services healthy, startup ingestion indexed 12/12 docs (`reports/docker_smoke.json`) |
| Kubernetes | `k8s/` manifests | Written; **not tested on kind** |

## Pipeline (`.github/workflows/ci.yml`)

1. **lint**: `ruff check` + `ruff format --check`
2. **test**: `pytest` with every API key empty (the app must work without keys)
3. **eval-gate**: `evals/retrieval_eval.py --gate` fails the build if recall@5 or MRR drop below
   `evals/gate.json`, or if the adversarial access-control test finds a single leak. No API key needed.
4. **docker**: builds the image and smoke-tests the container: `/health` up, `/ask` returns 503 without a
   key, `/search` returns the VPN runbook.
5. **deploy**: on push to `main`, on `v*` tags, or manually: uploads the checked-out ref to the Space.

## One-time setup (manual)

1. Create a Space: huggingface.co > New Space > SDK **Docker** > blank. Note its id (`your-name/orbitdesk`).
2. Space > Settings > **Secrets**: `GROQ_API_KEY` (and optionally `FALLBACK_PROVIDER_KEY`,
   `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST`).
   Space > Settings > **Variables**: `PROMPT_VERSION=v1`, `ROUTER_MODE=prompt`.
3. GitHub repo > Settings > Secrets and variables > Actions:
   secret `HF_TOKEN` (a Hugging Face token with **write** access), variable `HF_SPACE_ID=your-name/orbitdesk`.
4. Push to `main`. The deploy job is skipped with a warning until both are set.

## Monitoring

- `GET /health`: liveness + whether an LLM key, Redis and the vector store are available.
- Structured JSON logs (one line per HTTP request with `request_id`, latency, status; one line per
  `/ask` with per-stage timings and tokens). On the Space: Logs tab.
- `/ui` > **Admin** tab or `GET /admin/stats`: questions per day, failure rate, unanswered rate,
  average latency, cache hit rate, top unanswered questions, thumbs-down comments.
- Langfuse (when keys are set): one trace per request with every LLM call, agent step and tool call.

## Rollback

There are two levers, and they fix different problems.

**1. Code rollback (bad deploy): redeploy an older tag.**
Every release is tagged (`git tag v0.3.0 && git push --tags`, which also triggers a deploy). To roll back:
GitHub > Actions > `ci` > **Run workflow** > `ref = v0.2.0`. The workflow checks out that tag, runs the same
gates, and uploads it with `delete_patterns=["*"]`, so the Space becomes an exact copy of the old tag and
rebuilds. Rollback goes through the same gates as a forward deploy.

**2. Prompt rollback (answers got worse, code is fine): switch `PROMPT_VERSION`.**
Prompts are versioned files (`prompts/answer_v1.yaml`, `answer_v2.yaml`). Change the Space variable
`PROMPT_VERSION` (Settings > Variables) and restart the Space; no rebuild. The answer cache is namespaced
by prompt version, so answers generated by the bad prompt are not served after the switch.

The same applies to `ROUTER_MODE` (`finetuned` -> `prompt`) if the fine-tuned router misbehaves.

## Free-tier notes

- The Space's free CPU hardware is enough: the heavy local models (bge-small, MiniLM cross-encoder) are
  baked into the image, and generation runs on Groq.
- Space storage is ephemeral: SQLite tickets/feedback and runtime uploads reset on restart. The documents
  are re-ingested at build time, so the demo always works on a fresh container.
